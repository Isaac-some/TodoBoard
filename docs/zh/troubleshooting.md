# 故障排查

| 现象 | 检查与恢复 |
|---|---|
| App 提示后台未安装 | 用同一 `TODOBOARD_DATA_DIR` 运行安装器，检查 `runtime-install.json` 的 Python 和模块路径 |
| App 与后台看见不同任务 | 检查两个入口的数据目录；默认不使用旧个人 Board 目录 |
| Codex 找不到 | `defaultAgent.executable` 使用已安装客户端的绝对路径；确认后台所用用户已登录 |
| GUI 队列接口不支持 | 对照版本锁更新或选择 CLI 配置；原输入保留，不会显示假回执 |
| 已排队但没有执行 | 打开对应 Codex thread；处理原生信任提示、审批或登录。投递回执本身不代表已执行 |
| OV 404 / 401 / 离线 | 核对官方版本、客户端配置、用户 key、作用域与可读性；资料仍在本地队列 |
| 自动候选为空 | 检查归档成功凭据、`extraction.enabled`、模型可用性与原文证据；并非每份资料都含行动项 |
| 飞书授权失效 | 用对应 profile 重新授权；只补缺失 scope，不能通过切换身份绕过资源权限 |
| 会议没有逐字稿 | 可能尚未生成、未录制或当前账号无权限；覆盖范围保持未成功 |
| 执行结果不明 | 检查 deliveries 轨迹和原生会话，确认是否已有外部影响，再决定显式新请求 |
| JSON 损坏 | App 保存损坏文件并尝试最近备份；后台停止该写入，避免覆盖原文件 |

后台重启会重新处理未完成队列。对可能已经执行的 CLI 请求，启动标记阻止盲目重跑，卡片显示需要介入。OV 追加消息结果不明时同样保留凭据并等待核对；不会把网络失败简单解释为“肯定未写入”。
