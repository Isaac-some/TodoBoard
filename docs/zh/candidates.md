# 主动与自动候选

主动提交用于用户明确表达“把这件事记为 Todo”。资料立即在后台留存，候选立即进入 Board，不需要先等 OV 在线。

```bash
cd ~/Projects/TodoBoard
.venv/bin/todoboardctl submit-todo '核对发布说明' --notes '核对版本号与下载链接' --source-id release-note-review
```

提供稳定 `--source-id` 可以让调用方安全重试。MCP 的 `submit_todo` 提供相同能力。

自动提交只发生在 OV 会话成功归档并可读，或会议、本地资料成功归档之后。开启 `extraction.enabled` 后，后台调用配置的 Codex 模型并要求结构化输出。每个行动项必须包含原文中确实存在的证据；没有明确行动项就返回空列表。不要把每条工作记录都当成 Todo。

自动候选使用“原始来源 ID + 行动项标题”去重，不依赖采集批次。修改原文后，同一行动项不会重复入池。垃圾桶任务继续保留身份，重跑不会复活；标题实质改变的事项会作为新的候选，仍需人审核。

`backlog` 是候选；接纳、排序、丢弃和正式状态都由用户在 Board 操作。模型识别不代表承诺执行，分发成功也不代表完成。
